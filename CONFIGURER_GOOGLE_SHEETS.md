# Google Sheets order setup

Google Sheets synchronization is optional. Without the `GOOGLE_SHEETS_WEB_APP_URL` environment variable, orders are stored and managed in the AZ TECH administration system only; no request is sent to Google.

When configured, the storefront sends submitted orders to its `/api/orders` endpoint, which saves each order in the administration system and forwards it to the Google Apps Script web app. Orders are written to the `Commandes` tab in the spreadsheet with ID `1-8IlfZO8Pd17atBKQ7jG5N9AxS17kTTEf1_MCwlUrcU`. Each product is recorded on its own row in the sheet's existing column order: first name, last name, phone, address, quantity, and article; unit price and line total are written in columns G and H. Columns I:N store the order reference, status, the confirming/delivering/cancelling admin, and last modification time.

In `/admin`, the **Commandes** tab lets administrators review customer details, articles, totals and status; edit pending or confirmed orders; confirm, deliver or cancel them; filter by text, status, date and confirming admin; and view summary revenue and order activity. New orders show an in-dashboard notification. Status and edit actions also update the corresponding rows in Google Sheets.

After changing `google_sheets_orders.gs`, paste the whole file into the Apps Script project's `Code.gs`, save, then open **Deploy > Manage deployments > Edit**, select **New version**, and deploy. The live deployment should answer `AZ TECH orders endpoint is ready.` when opened with GET. It must execute as the spreadsheet owner and allow access to anyone, including people not signed in. If it redirects to Google sign-in or rejects an update, the order remains visible in the admin panel with a Sheets synchronization warning. To enable synchronization, set `GOOGLE_SHEETS_WEB_APP_URL` to the deployment's `/exec` URL in the hosting provider's environment variables, then redeploy the website. Leave it unset to keep Google Sheets disabled.

The first received order creates the `Commandes` tab and its column headers; on an existing sheet, columns G:N are filled only when their headers are empty. Product IDs and prices are checked against the storefront catalogue by the server; keep the fallback `ORDER_CATALOG` in `google_sheets_orders.gs` in sync with the storefront and confirm the sample listings (IDs 13-23) against actual stock.
